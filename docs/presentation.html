03 / SOLUTION

The Answer

Build the tool that doesn't exist yet.

THE TRACKER is a personal athlete performance platform, engineered from scratch around a specific Upper & Lower hypertrophy methodology — not adapted from a generic template.

🧠
Purpose-built
Designed around one specific training philosophy — Upper/Lower splits with rolling cycles.
📈
Progression-first
Every session shows last weight, last reps, and a computed suggestion for the next load.
🔒
Fully owned
No subscriptions. No lock-in. Self-hosted on Vercel + Supabase with full data control.

10 / SECURITY

Authentication & Security

Multi-layer defense in depth

🔐 Authentication Flow
1️⃣ Google OAuth 2.0 via Supabase Auth
↓
2️⃣ /auth/callback exchanges code for JWT
↓
3️⃣ DB trigger auto-creates profiles row
↓
4️⃣ Middleware refreshes session on every request
Row-Level Security (RLS)
Every table enforces data isolation at the database layer:
USING (auth.uid() = user_id)
WITH CHECK (auth.uid() = user_id)
RBAC — Role Hierarchy
user Own data only
admin Exercise + template management
super_admin Full system access + user roles
Route Protection
proxy.ts → check session
No session → redirect /login
Admin route → verifyAdmin()
Wrong role → throw 403

17 / SCALABILITY

Performance & Scalability

Engineered to grow without refactor

🏗️ Feature-Based Architecture
Each feature (workouts, exercises, weight, records) is a fully self-contained module with its own components, services, actions, and types. Adding a new feature never touches existing modules.
⚡ Server Components by Default
Pages are React Server Components — zero client JS shipped for data fetching. Only interactive islands are marked "use client". Minimizes bundle size and maximizes performance.
🗄️ Database-Level Security
RLS on every table means no application-layer filtering needed. Even direct API access cannot bypass data isolation. Scales to multi-user scenarios without code changes.
📦 Modular Migration Chain
11 sequential, versioned SQL migrations. Each migration is idempotent with IF NOT EXISTS guards. New features add new migrations — existing data is never at risk.
